# freelance_search — выжимка решений и граблей (02.10.2026)

Источник: пробный прогон плейбука `skill-tool` (issue #53), план `302d321a`,
issue #33, PR #34 + фикс #36. Сценарий: `docs/user-scenarios/freelance/02-freelance-search.md`.

## Что сделано

Тул `freelance_search(query, project_id?, limit?)` — read-only полнотекстовый поиск
по файлам пайплайна всех фриланс-проектов профиля. Совпадения `{project, file, line, snippet}`.
Без LLM, без сети, без записи.

## Решения (почему так)

- **Ошибки ввода — объект ответа (`isError`), не исключение.** Сервер скила пробрасывает
  `isError` наружу; оба контракта (песочницы и сценария) выполнены без правки тестов.
- **Итерация по записям индекса, не grep по корню хранилища** — профильные `_index.json`
  и `_classifier/` не попадают в результаты.
- **Рекурсивный обход папки проекта, а не фиксированный список файлов** — список застареет
  при росте пайплайна; обход ограничен папкой проекта и защищён капами.
- **`limit` — параметр (1..1000, по умолчанию 100), не константа** — требование
  «лимит + признак первые N» становится проверяемым (`truncated:true`, `total`).
- **Substring + регистронезависимость, без regex** — ровно запрос сценария; regex/семантика
  остаются в не-целях.

## Грабли (что узнали)

1. **Документированный ≠ объявленный в схеме.** `limit` был в описании и хендлере, но не в
   `inputSchema` → слой вызовов приводил аргументы ПО схеме, параметр приходил строкой,
   валидация отвергала. В проде возможность была недостижима у всех, хотя README обещал.
   Фикс: объявить в схеме (PR #36) + ужесточить тест контракта. Правило: каждый параметр
   из описания обязан быть в `inputSchema`.
2. **Мерж в скил ≠ прод.** Скилы на сервере обновляются только при деплое ядра; проверять
   `merge-base --is-ancestor <merge-sha> HEAD` в чекауте скила, а не версию ядра и не
   зелёный deploy-джоб. Новый тул виден только в НОВОЙ сессии.
3. **Живой вызов ловит то, что реплей не ловит.** Реплей зовёт тул напрямую через MCP-процесс;
   живой вызов идёт через слой агента с приведением типов по схеме. Гейт «реальный вызов»
   обязан включать граничные параметры из описания, а не только happy-path.
