# User Scenarios

Живая документация пользовательских сценариев домена freelance. Используется как:
1. **Спецификация поведения** — что должен делать скилл, точно и без двусмысленностей
2. **Основа для тестирования** — каждый шаг сценария = replay-кейс
3. **Онбординг** — новый разработчик читает сценарии и понимает систему

## Структура

```
docs/user-scenarios/
  README.md                     ← этот файл
  freelance/
    01-freelance-project-spec.md ← intake → факты/требования/решение → GO/NO-GO
```

## Формат сценария

Каждый `.md` файл содержит:
- **Контекст** — что уже есть у пользователя (state), какие токены подключены
- **Шаги** — реплики пользователя → ожидаемое поведение
- **Validation** — что именно проверяем (конкретно: файл создан, API вызван, текст содержит)
- **Edge cases** — граничные случаи
- **CI-сценарий: план моков** — что мокаем и чем (часть определения сценария, не постфактум)

## Mocks — ровно два рубежа

По `docs/domain-skill-repo-test-rules.md` §0 мокаются ровно **два** рубежа, и ни
один из них — не сервис:

| Рубеж | Чем мокаем |
|---|---|
| LLM | скриптованные ответы (`fixtures/llm/*.json`) на loopback |
| Внешняя сеть (OpenRouter/GDrive/…) | loopback-only + изолированные токены |

`risk-engine` (`lib/risk-engine.js`) детерминирован — **не мокается**. Регистратор
(`registry.js`) не мокается никогда.

## Исполняемые сценарии

Документ описывает поведение; replay-шаги живут рядом в `scenarios/<name>/` и
исполняются детерминированным гейтом:

- `scenarios/freelance-intake/` → `tests/replay/01-intake-pipeline.spec.mjs`
- `scenarios/freelance-classifier-routing/` → `tests/replay/02-classifier-routing.spec.mjs`

Запуск: `npm run test:replay` (см. `docs/skill-ci.md`).
